# scenarios-and-degradation — 需求规格

## 概述

实现四类业务场景（订单/维修/安全/普通问候）的差异化渲染、订单 6 种状态、degraded 与 error 视觉规格，以及桌面优先的小屏降级（右栏与左栏抽屉）。

## 项目信息

- 项目名: ai-kefu
- 架构类型: 多包单仓
- 需求来源: `docs/智修客服AI工作台-前端需求.md` §6.2、§7、§8

## 用户故事

- 作为客服坐席，我想在订单查不到时看到明确原因与重试入口，以便立刻决定下一步。
- 作为客服坐席，我想在窄屏笔记本上仍能查看处理依据，以便外出时也能核对结论。

## 功能需求

### 场景差异化

1. [F-001] **订单类**（`route === "order"`）：在 AI 正文下方渲染订单卡片（复用回答模式卡样式 `bg content-bg border p-4`），6 种状态：
   | 状态 | 判定 | 展示 |
   |---|---|---|
   | 成功 | `found === true && !partial` | 正常信息卡，左边框 `success-green` |
   | 部分缺失 | `found === true && partial === true` | 卡片 + 12px「部分信息缺失：{missingFields.join("、")}」 |
   | 不存在 | `error === "not_found"` | safety 卡「订单不存在，请核对订单号」 |
   | 超时 | `error === "timeout"` | safety 卡「订单服务响应超时」+ 重试 |
   | 服务错误 | `error === "server_error"` | safety 卡「订单服务异常，请稍后再试」 |
   | 网络错误 | `error === "network_error"` | safety 卡「网络异常，无法连接订单服务」+ 重试 |
2. [F-002] 未提供订单号时服务端先追问、不调用工具 → 前端 `toolCalls` 无 `queryOrderTool`，**不渲染**订单卡片与「已调用 · 订单服务」节点。
2a. [F-002a] `[v2 新增]` 订单卡片的详情字段**只能读取 `order.details`**（类型化白名单，由 `1.T-007` 提供）。
    ⛔ **禁止**解析泛型 `toolCalls[].result`；⛔ 禁止读取白名单之外的任何键。
2b. [F-002b] `[v2 新增]` `details` 的 10 个字段**全部可空**，UI 必须逐字段做空值处理：
    字段为 `null`/`undefined` 时**隐藏该行**（或显示「—」），⛔ 不得臆造默认值或占位文案。
2c. [F-002c] `[v2 新增]` `details` 为 `undefined` 时（如 `found: false`），只渲染状态卡，不渲染详情区。
2d. [F-002d] `[v2 新增]` 可展示字段固定为：`orderId`、`status`、`statusText`、`createdAt`、
    `carrier`、`trackingNumber`、`latestLogistics`、`estimatedDelivery`、`canCancel`、`customerTip`。
3. [F-003] **维修类**（`repair`）：正文多段与编号步骤按 1.6/1.7 行高渲染；引用角标用 `description` 图标；`sources` 为空时不渲染角标与来源列表，且回答模式不显示 `RAG知识增强`。
4. [F-004] **安全类**（`safety`）：正文**必须**渲染安全提示卡（`border safety-border` + `bg safety-bg` + `warning` 图标 + `text safety-text`，`my-4 p-3`）；引用角标安全类用 `security` 图标。安全话术来自服务端正文，⛔ 前端不硬编码。
5. [F-005] **普通问候**（`general`）：仅渲染正文与操作行；**不渲染**引用角标、安全卡、订单卡；右栏仅两个节点 + 仅 `本地QLoRA`，引用区显示「本次回答未引用知识库」。
6. [F-006] 正文引用角标：`bg citation-bg`，`text citation-text`，12px，`px-3 py-1.5`，图标 14px，文案 `[序号] {title} · {section}`，`hover:opacity-80`。

### 异常态

7. [F-007] **degraded**（`degraded === true`）：不阻断正文；右栏追加「降级运行」chip 与 `degradedReason`；⛔ 不直改顶栏，改为触发 `status()` 刷新。
8. [F-008] **error**：AI 气泡位置渲染错误卡（`border safety-border bg safety-bg p-3` + `warning` + bold「回复生成失败」+ 14px message + 12px traceId）；提供 `refresh 重试` 按钮以相同入参重发；右栏保留已收到节点并追加红色「已中断 · 生成失败」；**已收到的部分正文保留不清空**。
9. [F-009] **空状态**：消息流居中显示标题 + 副标题 + 4 个快捷 chips。
10. [F-010] **取消**：`AbortError` 不显示错误提示，保留已生成内容（与 `5.F-013` 一致）。

### 响应式

11. [F-011] 断点行为（全部来自 HTML 实读）：
    | 断点 | 行为 |
    |---|---|
    | ≥1280px | 右栏 320px，三栏完整 |
    | 1100–1279px | 右栏 300px，三栏完整 |
    | 768–1099px | **右栏隐藏**，左栏 + 中间区 |
    | <768px | **左栏隐藏**、顶栏状态与副标题隐藏、清空会话只剩图标、对话头部转纵向、消息区 `px-4`、正文 15px |
12. [F-012] <1100px 时，对话头部提供 `memory` 图标入口，点击以**右侧抽屉**展示完整处理依据，内容与右栏 100% 一致。
13. [F-013] <768px 时，顶栏左侧提供菜单入口，点击以**左侧抽屉**展示会话列表与新建会话。
14. [F-014] 抽屉规格：0 圆角、背景同原栏位、200ms ease-out、遮罩 `rgba(36,49,66,0.4)`。
15. [F-015] **任何断点下 body 不得出现横向滚动**。

## 非功能需求

- **健壮性**: 6 种订单状态、3 种异常收尾均须有确定 UI，不出现空白或残留「生成中」。
- **可访问性**: 抽屉需支持 Esc 关闭与焦点管理；错误信息不单靠颜色传达。
- **安全**: 错误卡只展示服务端 `message` 与 `traceId`，不展示堆栈或内部地址。
- **兼容性**: 桌面优先；小屏为降级方案，非独立设计稿。
