# quality-gates-and-design-review — 需求规格

## 概述

落地 8 项质量门禁（typecheck / build / UI 组件测试 / Mastra smoke / 直连扫描 / 计数硬编码扫描 / 资产完整性 / 设计复核），并完成设计还原验收，作为整个改造的横切验收关口。

## 项目信息

- 项目名: ai-kefu
- 架构类型: 多包单仓
- 需求来源: `docs/智修客服AI工作台-前端需求.md` §9、§10、§1.5.2

| 日期 | 版本 | 说明 |
| ---- | ---- | ---- |
| 2026-07-31 | v1 | 初始需求 |
| 2026-07-31 | v2 | 门禁 5 禁连端口由 5 个扩为 6 个（新增 Ollama Embedding 11434） |

## 用户故事

- 作为 reviewer，我想要一条命令跑完全部门禁，以便在合入前确认没有踩到任何硬约束。
- 作为设计负责人，我想要可复现的还原比对流程，以便判定实现是否忠于设计稿。

## 功能需求

1. [F-001] **门禁 1 typecheck**：`npm run typecheck` 0 error。
2. [F-002] **门禁 2 build**：`npm run build` 成功，无错误级告警。
3. [F-003] **门禁 3 UI/组件测试**：Vitest + Testing Library，须覆盖：
   - 四类 route（safety/order/repair/general）
   - 5 类流式事件
   - degraded / error / 空状态 / 取消
   - 订单 6 种状态
   - **`status()` 5 项测试**（四态渲染、聚合三分支、初始 unknown、超时与失败、脱敏断言）
4. [F-004] **门禁 4 Mastra Client smoke**：`npm run smoke` 对 `:4111` 真实往返成功，覆盖 chat / stream / status 三个端点。
5. [F-005] **门禁 5 禁止直连扫描**：源码扫描 **6 个端口**与绕过用法，0 命中。
   `[v2 修改]` 端口清单：`8000` FastAPI、`8001` Mock 后端、`8002` llama-server、
   `6333` Qdrant、`8787` Reranker、**`11434` Ollama Embedding（v2 新增）**。

   ```bash
   grep -rnE ':(8000|8001|8002|6333|8787|11434)|getAgent\(' web-client/src \
     --include='*.ts' --include='*.tsx' \
     && { echo '❌ 检测到禁止的直连或绕过用法'; exit 1; } || echo '✅ 无直连'
   ```

6. [F-006] **门禁 6 计数硬编码扫描**：召回/重排文案附近不得出现 20 / 5 字面量，0 命中。

   ```bash
   grep -rnE '(已召回|重排完成|Top)\s*[·:]?\s*(20|5)\b' web-client/src \
     --include='*.ts' --include='*.tsx' \
     && { echo '❌ 检测到召回/重排计数硬编码'; exit 1; } || echo '✅ 无硬编码计数'
   ```

7. [F-007] **门禁 7 资产完整性**：`shasum -a 256 -c` 比对 §1.5.1 基线全部 OK。
8. [F-008] **门禁 8 设计复核**：Stitch MCP 重新拉取 screen 或浏览器截图，与实现并排比对，符合 §9.1。
9. [F-009] 组件层不得出现 `fetch(` / `axios` / `new MastraClient(`，所有网络调用溯源到 `web-client/src/client.ts`。
10. [F-010] 设计还原验收 9 项（截图对比 / 颜色 / 字体 / 圆角 / 间距 / 层级 / 滚动 / 空状态 / 图标）全部达标。
11. [F-011] 截图比对时，需求 §1.6 的三处已知截图偏差（顶栏 3 状态点、右栏 6 执行节点、第 4 个 chip）**不判为不一致**；反之实现中缺失任一项判为还原缺陷。
12. [F-012] 提供一条聚合命令（如 `npm run gates`）串联可自动化的门禁 1/2/3/5/6/7。

## 非功能需求

- **可重复性**: 门禁脚本可在本地与 CI 一致执行，不依赖交互输入。
- **明确失败**: 任一门禁失败须非零退出并打印可定位的原因。
- **性能**: 自动化门禁整体执行时间可接受（建议 < 5min）。
